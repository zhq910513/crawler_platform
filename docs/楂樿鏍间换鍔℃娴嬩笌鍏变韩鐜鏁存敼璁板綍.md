# 高规格任务检测与共享环境整改记录

## 本轮结论

本轮已将执行理念从“单纯每个任务独立容器”升级为：

> 项目环境镜像 + 独立任务容器。

即：一个项目构建一个不可变镜像环境，同项目任务共享镜像层和项目缓存卷；每个运行实例仍拥有独立 Docker 容器、工作目录、日志目录、Profile 目录、资源限制、超时和租约。

这解决了“一个项目就是一个环境”的诉求，同时保留任务级故障隔离。

## 已完成改造

1. 后端任务定义、正式任务、运行实例新增运行策略字段：`runtimeMode`、`taskGroup`、`taskMaxConcurrency`、`groupMaxConcurrency`、`exclusiveMode`、`ioClass`、`shmSizeMb`、`logLimitMb`、`resourceLocks`。
2. 路由器在选服务器前增加任务级并发、任务组并发、独占运行和资源锁检查。
3. Agent claim 下发项目、任务和运行策略快照：`projectCode`、`taskCode`、`runtimeMode`、`taskGroup`、`shmSizeMb`、`logLimitMb`、`resourceLocks` 等。
4. Agent 创建任务容器时挂载标准项目目录：`/cache`、`/work`、`/logs`、`/profiles`、`/tmp/crawler-run`。
5. Agent 任务容器增加 CPU、内存、shm、pids、日志滚动、安全标签和 no-new-privileges 配置。
6. 单机部署脚本和 Agent compose 增加项目数据目录挂载。
7. 前端创建任务时支持配置运行模式、任务组、并发、IO 类型、独占运行、shm、日志上限和资源锁。
8. CI/CD manifest 和 `sch.py` 静态 TASKS 支持运行策略字段。
9. 新增测试覆盖共享环境运行策略 claim 下发、资源锁冲突阻塞。

## 业务建议

- 默认使用 `SHARED_ENV_ISOLATED`。
- 浏览器任务建议设置更大的 `shmSizeMb`，并按任务组限流。
- 登录任务建议开启 `exclusiveMode` 或配置账号/Profile 资源锁。
- 高 IO 下载任务建议配置独立任务组和较低 `groupMaxConcurrency`。
- `WORKER_POOL` 暂作为预留模式，待容器内 supervisor 完成后再启用。
