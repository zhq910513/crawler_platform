# 共享环境隔离运行模式

本平台的默认执行模式冻结为：**项目环境镜像 + 独立任务容器**。

## 核心原则

- 一个项目构建一个不可变镜像环境，任务运行时统一使用 `imageRepository@sha256:digest`。
- 同一项目下的任务共享镜像只读层和项目缓存卷，不重复复制依赖环境。
- 每个运行实例仍启动独立任务容器，拥有独立工作目录、日志目录、Profile 目录、资源限制和超时控制。
- 平台数据库仍是任务、调度、并发、状态、告警、审计的唯一事实来源。
- 常驻 Worker 池保留为后续增强模式，不作为默认上线模式。

## 目录规范

Agent 在执行服务器上维护项目数据根目录，默认：

```text
/data/crawler-platform/projects/{projectCode}
├── cache/                 # 项目共享缓存，可被同项目任务复用
├── work/{runId}/           # 单次运行独立工作目录
├── logs/{runId}/           # 单次运行独立日志目录
├── profiles/{taskCode}/{runId}/ # 单次运行独立浏览器 Profile
└── tmp/{runId}/            # 单次运行临时目录，结束后清理
```

任务容器内部挂载：

```text
/cache
/work
/logs
/profiles
/tmp/crawler-run
```

## 任务运行策略字段

任务定义和正式任务支持：

- `runtimeMode`：`SHARED_ENV_ISOLATED`、`WORKER_POOL`、`DEDICATED_CONTAINER`。
- `taskGroup`：任务组，例如 `api`、`browser`、`download`、`login`。
- `taskMaxConcurrency`：单任务最大并发。
- `groupMaxConcurrency`：同项目同任务组最大并发。
- `exclusiveMode`：独占模式，运行时阻止同项目其他任务释放路由。
- `ioClass`：`LOW`、`NORMAL`、`HIGH`。
- `shmSizeMb`：容器 `/dev/shm` 大小，浏览器任务建议提高。
- `logLimitMb`：单容器 Docker 日志滚动上限。
- `resourceLocks`：资源锁，例如 `account:amazon_us`、`profile:feishu`、`proxy:de_01`。

## 路由控制

路由器在选择服务器前先检查：

1. 任务级并发是否已满。
2. 任务组并发是否已满。
3. 独占任务是否可以运行。
4. 资源锁是否被占用。
5. 服务器、Agent、项目服务器池、镜像状态、能力标签和容器槽位是否满足。

不满足时运行实例进入 `WAITING_RESOURCE`，不会丢失 Cron 触发。

## Agent 执行

Agent 领取运行实例后：

1. 按 digest 拉取并校验项目镜像。
2. 创建项目共享缓存目录和运行隔离目录。
3. 以独立任务容器启动 `python -m crawler_runtime --entrypoint module:function`。
4. 按任务限制设置 CPU、内存、shm、pids、日志大小、标签和安全选项。
5. 任务完成后删除容器，保留 work/logs/cache/profiles 便于排错和复用。

## 适用建议

- 默认使用 `SHARED_ENV_ISOLATED`。
- 浏览器、高 IO、高内存、非幂等或登录任务建议设置更低并发、资源锁或 `DEDICATED_CONTAINER`。
- 高频轻量任务后续可以使用 `WORKER_POOL`，但必须有容器内 supervisor 后才能启用。
