# 零数据测试服验收步骤

本项目测试服按 Fresh Install 验收：空 MySQL、空 Redis、空项目数据目录开始，不做历史数据兼容、不做旧状态回填。

## 一、验收目标

完整验证以下链路：

```text
空库初始化 → 超级管理员登录 → 创建公司 → 注册 Agent → 构建并推送测试爬虫镜像 → 上报待接入项目 → 接入正式项目 → 创建正式任务 → 配置执行服务器池 → 手动触发任务 → Agent 按 digest 拉镜像 → 启动共享环境隔离任务容器 → 回传成功结果
```

## 二、前置条件

测试服必须具备：

- Docker Engine
- Docker Compose v2
- Python 3
- 可访问 PyPI / npm registry / Docker Hub / 本地或远程镜像仓库
- 当前用户具备 Docker 操作权限
- 8080、3306、6379、5000 端口未被冲突占用，或已在 `.env` 中调整

## 三、一键 Fresh Install 验收

在项目根目录执行：

```bash
./deploy/scripts/test-server-validate.sh --yes
```

该命令会清空测试服本地数据并执行完整核心验收，包括构建平台、初始化空库、启动服务、构建 smoke 爬虫镜像、启动真实 Agent、创建并运行测试任务。

如果已经手工完成 Fresh Install，只想跑 smoke-test：

```bash
./deploy/scripts/test-server-validate.sh --yes --skip-reset
```

## 四、分步验收命令

生成 `.env` 并执行零数据重置安装：

```bash
./deploy/scripts/reset-test-server.sh --yes
```

检查平台健康：

```bash
curl -fsS http://127.0.0.1:8080/health
```

执行真实 Agent + 真实任务容器链路：

```bash
./deploy/scripts/smoke-test.sh --build-smoke-image --start-agent
```

查看服务状态：

```bash
docker compose ps
```

查看 API 日志：

```bash
docker compose logs --tail=300 api
```

查看调度器日志：

```bash
docker compose logs --tail=300 scheduler
```

查看维护任务日志：

```bash
docker compose logs --tail=300 maintenance
```

查看 Web 日志：

```bash
docker compose logs --tail=200 web
```

查看 smoke Agent 日志：

```bash
docker logs --tail=300 crawler-agent-smoke
```

查看项目共享环境目录：

```bash
find /data/crawler-platform/projects -maxdepth 4 -type f | sort | head -100
```

## 五、前端构建验收

测试服具备 npm registry 访问能力时执行：

```bash
cd frontend && npm ci && npm run build
```

Docker 构建会使用 `npm ci`，如该命令失败，不允许上线。

## 六、MySQL 空库验收

执行迁移：

```bash
docker compose run --rm migrate
```

检查表结构：

```bash
docker compose exec mysql mysql -uroot -p$MYSQL_ROOT_PASSWORD crawler_platform -e "SHOW TABLES;"
```

检查核心数据：

```bash
docker compose exec mysql mysql -uroot -p$MYSQL_ROOT_PASSWORD crawler_platform -e "SELECT user_id,user_name,role_type,status FROM sys_user; SELECT company_id,company_code,company_name,status FROM crawler_company; SELECT project_id,project_code,online_status FROM crawler_project; SELECT task_id,task_code,status,runtime_mode,task_group FROM crawler_task; SELECT run_id,run_status,routing_status,server_id FROM crawler_task_run ORDER BY run_id DESC LIMIT 20;"
```

## 七、几百任务压测建议

Fresh Install 核心链路通过后，再执行压测。建议至少验证：

- 1 个公司
- 1 个项目
- 300 个任务定义
- 同一时间创建 100 个 run
- 项目最大并发、任务最大并发、任务组并发、资源锁均生效
- Agent 不会一次性启动超过 slot 的任务容器
- `WAITING_RESOURCE` 不丢任务
- MySQL、Redis、Docker、API、Agent 均不出现持续异常

压测脚本可在核心链路稳定后单独添加，不应和 Fresh Install 主验收混在一起。

## 八、P0 告警验收

在前端“系统设置 → 告警通知”配置飞书、企业微信、钉钉或邮箱后执行测试通知。

需要确认：

- 测试通知发送成功
- Webhook 非 2xx 被记录为失败
- P0 事件可以确认
- P0 事件可以恢复
- 冷却时间生效

## 九、备份恢复验收

执行备份：

```bash
./deploy/scripts/backup.sh
```

至少在测试服做一次恢复演练，确认备份文件可用。生产上线前必须完成该项。

## 十、通过标准

必须全部满足：

- `docker compose config` 通过
- `docker compose build --pull` 通过
- `docker compose up -d` 后服务健康
- `curl /health` 通过
- `migrate` 在空 MySQL 上通过
- `smoke-test.sh --build-smoke-image --start-agent` 通过
- 前端 `npm ci && npm run build` 通过
- Agent 成功启动真实任务容器并回传 `SUCCEEDED`
- 项目共享目录出现 `/cache`、`/work`、`/logs`、`/profiles` 运行产物
- 无旧 bootstrap 接口、旧 Agent token、ORM 自动建表残留
